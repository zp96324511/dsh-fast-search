# P0 基准报告：会话全文搜索的可行性与架构选型

> 目标机：Windows 10 / Node v26.10.0 / `node:sqlite`（内置 SQLite + FTS5）
> 语料：`C:\Users\win10\.dsh\sessions` 下全部 5,408 个 `session.v4.jsonl.zstd`
> 判定门槛：全量建索引 < 180s；稳态单次查询 P50 < 50ms
> 复现：`pwsh -NoProfile -Command "node bench/p0-bench.mjs --all --sort-size"`

## 1. 结论摘要

| 门槛 | 实测 | 结论 |
| --- | --- | --- |
| 全量建索引耗时 | **24.4s**（单库 s2，59,250 文档 / 56.0MB 文本） | 通过（远低于 180s） |
| 稳态查询 P50 | **4.6ms**（命中）/ **9ms**（命中+摘要，典型词） | 通过（远低于 50ms） |
| 最坏查询 | 27ms（单字 `的` / `the`，命中 5 万+ 文档） | 通过，但仍需降级策略 |
| 索引体积 | **99.3MB**（FTS5 + 原文本） | 可接受 |
| 中文召回正确性 | 与全表字面扫描**逐条一致**（477/477、26/26、1037/1037、934/934） | 通过 |

**架构决定（7 条，均以本节数据为依据）**

1. **放弃 trigram（s3）**：2 字中文词（插件/搜索/索引/会话/基准/的）召回率 **全为 0**，而这正是中文检索的主要形态；且索引 214.2MB，是另两个方案的 2.2 倍。
2. **采用「逐字插空格 + 引号短语」（s2）**：索引期把每个 CJK 字符扩成 ` 字 `，中文即退化为单字 token；查询期把 CJK 词拆成 `"插 件"` 短语。索引体积 99.3MB ≈ s1 的 96.7MB，**几乎零额外成本**。
3. **不用 `snippet()`**：它是查询耗时的绝对主因（25–105ms，是命中耗时的 3–5 倍），因为它对 300 条 × 8KB 文本重新分词。改为两阶段：先取命中 → 只对展示的 ~20 条取文本，在 JS 里做窗口与高亮。
4. **必须开 `PRAGMA mmap_size=268435456`**：这是最大的单项优化，hits P50 **16.1ms → 4.6ms（3.5×）**，max 29.1ms → 13.2ms。`cache_size` 在其之上无增益（4.77ms），不开 mmap 一切调优都无意义。**必须每次连接时设置**（不随库持久化）。
5. **`ORDER BY bm25()` 保留**：去掉排序后 1ms 级，但相关性会塌。bm25 排序的残差成本（mmap 下 3–13ms）可以接受。
6. **单库单表 + 元数据列**，不拆多表、不做外部内容表；`text` 列存「插过空格」的文本，展示前用 `cjkUnspace()` 精确还原（已在真实数据上验证，见 §5.3）。
7. **RPC 走宿主 `webServer` 前缀路由 + JSON POST**，不用 Typert remote 命名空间（样板简单、够用，见 `dsh-active-sessions` 的注册方式）。

## 3. 解码与建索引

分阶段耗时（一次遍历同时插 s1/s2 两库）：

| 阶段 | 耗时 |
| --- | --- |
| 目录遍历（walk） | 564ms |
| 读文件 | 2,380ms |
| zstd 解压 | 2,920ms |
| JSON 解析 + 文本抽取 | 3,895ms |
| FTS5 插入 s1（unicode61） | 12,792ms |
| FTS5 插入 s2（unicode61 + 插空格） | 14,597ms |
| **合计（两库）** | **38,155ms** |
| **单库折算（s2）** | **≈ 24.4s** |

- 每文件耗时：P50 **1.1ms**、P95 **4.7ms**、max **1,782.6ms**（单个超大文件）。
- 解码错误 0、坏行 0、不支持类型 0。
- 插入是唯一的大头（占 60%），但已远低于门槛，不需要批量事务优化；增量场景下每文件约 1–3ms，可以做到「改一个会话 5ms 内入库」。

索引体积：

| 库 | 分词 | 体积 |
| --- | --- | --- |
| s1 | `unicode61 remove_diacritics 2` | 96.7MB |
| s2 | 同上 + CJK 逐字插空格 | **99.3MB** |
| s3 | `trigram` | 214.2MB |

**插空格几乎不放大索引**（+2.7%），因为 unicode61 仍按单字建索引，只是把"连续中文=一个 token"改成"一字一 token"。

## 5. 查询路径

### 5.1 `snippet()` 必须移除

默认 pragma、300 条上限下，命中 vs 带摘要：

| 查询 | 命中 P50 | 带 `snippet()` P50 | 倍数 |
| --- | --- | --- | --- |
| 插件 | 7.86 | 36.92 | 4.7× |
| 会话 | 10.80 | 70.85 | 6.6× |
| 工作区 | 7.38 | 52.72 | 7.1× |
| 的 | 23.67 | 105.07 | 4.4× |
| the | 23.84 | 70.63 | 3.0× |

`snippet()` 对每一条命中都要重新分词、重新读原文，属于"为 300 条结果做 300 次摘要"的浪费。改为两阶段后，摘要成本降到"只处理展示的 20 条"。

### 5.2 调优矩阵（s2，30 次迭代取 P50）

| 查询 | default 命中 | mmap 命中 | mmap+cache 命中 | mmap 下 hits100 | mmap 下无排序 | mmap 下 hits300+批量取20文本 |
| --- | --- | --- | --- | --- | --- | --- |
| 插件 | 10.26 | **4.64** | 3.58 | 3.30 | 1.25 | 4.14 |
| 搜索 | 10.98 | **2.78** | 3.26 | 1.87 | 1.28 | 2.83 |
| 会话 | 18.47 | **6.10** | 5.78 | 3.85 | 0.85 | 6.22 |
| 索引 | 9.76 | **2.57** | 2.61 | 1.65 | 1.04 | 2.38 |
| 工作区 | 16.08 | **3.97** | 4.77 | 2.59 | 0.86 | 4.28 |
| PowerShell | 12.31 | **4.14** | 4.65 | 2.16 | 0.77 | 3.82 |
| session | 16.32 | **6.94** | 6.84 | 5.74 | 1.00 | 6.84 |
| 的 | 26.93 | **13.21** | 13.34 | 11.19 | 1.01 | 13.59 |
| the | 29.10 | **13.09** | 14.17 | 9.60 | 0.82 | 13.41 |
| **中位数** | **16.08** | **4.64** | 4.77 | — | ~1 | — |

要点：

- **mmap 是 3.5× 的单项优化**，原因是一次命中要随机读 FTS 段页，页缓存（默认 2MB）命中率极低。
- `cache_size=-131072` 在 mmap 之上无增益 → 配置里只留 mmap。
- **无排序（no-sort）≈1ms**：说明 bm25 打分/排序是 mmap 下的主要残差，但换掉的代价是丢掉相关性，不值得。
- 「hits300 + 批量取 20 条文本」与「hits300」几乎同价（+0–0.5ms），因为 20 条 8KB 文本走 `json_each` 一次点查。**逐条点查（20 次 `rowid = ?`）与批量同价**，实现上可选简单的那种。
- `hits100` 约为 `hits300` 的 55%——列表分页若要更快可以把上限降到 100，但 300 才能保证"按会话分组后仍有 20+ 个不同会话"，**保留 300**。

**最终稳态查询预算（mmap，典型中文词）**：命中 3–7ms + 取文本/还原/高亮 3–4ms ≈ **6–11ms**；重词（的/the）≈ 27ms。

### 5.3 展示文本还原（`cjkUnspace`）

索引里存的是插过空格的文本，直接展示会变成「插 件」。还原函数必须与 `cjkSpace` 严格互逆：

```js
// 索引期
const cjkSpace = (s) => s.replace(/[\u3400-\u4DBF\u4E00-\u9FFF\uF900-\uFAFF\u3040-\u30FF\uAC00-\uD7AF]/g, (c) => ` ${c} `);

// 展示期：删掉为每个 CJK 字符插入的那一个前导空格，并跳过其后的那一个空格
function cjkUnspace(s) {
  let out = '';
  for (let i = 0; i < s.length; i++) {
    const ch = s[i];
    if (isCJK(ch) && out.endsWith(' ')) out = out.slice(0, -1);
    out += ch;
    if (isCJK(ch) && s[i + 1] === ' ') i++;
  }
  return out;
}
```

只删「自己插入的那一个」空格，因此原文本来就有的空格（如 `hello 世界`）不会被吃掉。已用真实数据抽样验证：还原后与原始文本逐字符相等。

## 6. 最终选型

```
存储（单个 SQLite 文件，约 100MB / 6 万文档）
  docs(text, session_id, seq, type, role, time)   -- FTS5 external? 否，普通 FTS5 表
    tokenize = 'unicode61 remove_diacritics 2'
    text 列内容 = cjkSpace(原文)，展示前 cjkUnspace 还原
  sessions(session_id PK, cwd, parent_id, created_at, title)
  file_state(path PK, session_id, size, mtime_ms, line_count)   -- 增量用

写入
  遍历 *.jsonl.zstd → zstdDecompressSync → 行级 JSON.parse（按 type 预筛）
  单事务批量插入；WAL；增量时按 file_state 的 size+mtime 判定重解

查询（两阶段）
  1) SELECT rowid, session_id, seq, type, role, time, bm25(docs) AS score
       FROM docs WHERE docs MATCH ? ORDER BY score LIMIT 300
     MATCH 构造：每个词包成 "..."，CJK 词先拆成单字再用空格连接；多词以空格 AND
  2) 对展示的 ~20 条 SELECT text WHERE rowid IN (json_each(?))
     → cjkUnspace → JS 窗口截取 + 多次命中高亮

连接参数（每次 open 必设）
  PRAGMA mmap_size = 268435456
  PRAGMA journal_mode = WAL（写连接）
```
